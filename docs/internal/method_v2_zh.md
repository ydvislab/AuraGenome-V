# A1 方法 v2 设计规格（2026-10-29，写于任何 v2 结果之前）

本文件和 v2 代码在同一个 commit 中提交，之后才在开发集上运行。目的：回应 Codex 研究评审（PROCEED WITH CAUTION，5/10）。评审指出，v1 在"匹配轨道可用"的部署场景下不如直接使用匹配轨道平均：有 7/11 个区域低 0.05 以上。

## 要回答的问题

同一个不看标签就定好的方法，能否同时做到：

1. **保住**：匹配轨道本来就准时，不比原样使用匹配轨道平均差；
2. **救回**：匹配轨道不准时，用 8 个实测值找到更好的轨道；
3. **不输简单对照**：不输给同样预算下以元数据为中心的简单校正。

## v2 相对 v1 的改动（只有三处）

1. **元数据锚点假设**：当元件的细胞类型有匹配轨道时（all 场景），把匹配轨道的平均预测作为一个额外假设 `anchor|matched`。它和单条轨道一样，按元件内标准差缩放。
2. **锚点的先验**：
   - 锚点的先验质量为 π，其余 1 − π 分给单条轨道。
   - 锚点的斜率先验以正值为中心：b ~ N(√β·s, (β/4)·s²)。这样预测为负斜率的先验概率约为 2.3%，"仿射拟合把匹配平均翻转"需要很强的数据证据。
   - 单条轨道的斜率先验不变，仍为 N(0, β·s²)。
3. **轨道家族先验**：
   - 单条轨道分得的 1 − π 先平均分给预测相关性聚类（平均连接，相关 ≥ 0.9，只用预测值、不用标签），再在类内平分。
   - 复制一条轨道只会让它落进原来的类，不改变其他轨道的先验，也不改变预测。
   - 这一项在两个场景都生效。hide_matched 场景没有锚点，所以 v2 = v1 + 家族先验。

其余全部沿用 v1：α = 0.1，β = 0.5，可测变异池 50%，200 次重复，seed 0，disc 选点规则，以及后验加权预测（主输出）。评估一律使用统一评估集（`--common-eval`）。

## 参数网格（事先声明，只有一个参数）

- π ∈ {0.5, 0.8, 0.95}。
- 每个 π 分别配"家族先验"和"均匀先验"两种。均匀先验是消融。
- 再加 π = 0（无锚点，只有家族先验）作为消融。

π 的选择准则：all 场景下，k = 8 时 v2 的 rho_bma 减去原样匹配平均，在开发元件上取平均，取最大者。
- 平局（差 < 0.005）取较小的 π，因为较小的 π 更容易救回。
- 用留一元件做敏感性分析：每次去掉一个开发元件重新选 π，报告所选 π 是否改变，以及被留出元件上的结果。

## 同预算简单对照（新增，all 场景）

都在 random 和 disc 两种选点上计算，k ∈ {4, 8, 16}，评估集与主方法相同。

- `matched`（已有）：原样使用匹配轨道平均，不用标签。
- `+matched_cal`：只用匹配平均这一个假设，按 v1 的对称斜率先验做仿射校正。用来显示翻转风险。
- `+meta_ridge`：以元数据为中心的收缩。先用正斜率先验把匹配平均校正到实测尺度，再对残差在所有轨道上做岭回归，惩罚用精确留一选。这是评审要求的"以元数据为中心的简单适配"。

## 开发集上看的量（描述性，5 个元件不做检验）

- 部署差 D_i = v2 − matched：平均、正负个数、损害数（D_i < −0.05 的元件数）。
- 救回：在 matched 明显不如最佳单轨道的元件上，v2 是否接近 v1 的增益。
- v2 与 `+meta_ridge`、`+matched_cal` 在同一选点上的差。
- hide_matched 场景：v2（家族先验）与 v1 的差。
- 锚点的后验质量，以及 disc_stop 是否因先验惯性提前停止（评审指出的风险）。

## 之后的顺序

1. 开发集选定 π，冻结 v2。冻结写入本文件末尾，与代码在同一个 commit。
2. 在 Kircher 检验集上运行冻结的 v2，作为描述性复核。按评审意见，Kircher 已是开发历史，这一步不算确证。
3. Siraj 预注册：写明非劣效界值 δ、损害率上限 (τ, q)、独立定义的救回条件，然后才查看 Siraj。

**停止条件（评审原话的约定）**：如果 v2 既不能超过以元数据为中心的简单适配，又不能在控制损害的前提下救回，就放弃"安全网"主张。

## 开发集结果（2026-10-29，写于运行之后）

说明：上面的规格写于 08:44，网格任务 08:45 开始。规格当时还没有提交，所以提交时间晚于结果；规格正文没有改过。

5 个元件，all 场景，k = 8，统一评估集，200 次重复。完整表见 `results/a1/v2_dev_configs.tsv`、`v2_dev_long.tsv` 和 `v2_dev_pi_choice.tsv`。

| 配置 | disc − matched | 为正 | 受损（< −0.05） | 最差 | 锚点后验质量 |
|---|---|---|---|---|---|
| v1 | −0.047 | 2/5 | 3 | −0.127 | — |
| π = 0（只有家族先验） | −0.063 | 2/5 | 3 | −0.169 | — |
| π = 0.5，家族先验 | −0.034 | 2/5 | 3 | −0.094 | 0.56 |
| π = 0.8，家族先验 | −0.016 | 2/5 | 1 | −0.056 | 0.73 |
| **π = 0.95，家族先验（按规则选中）** | **−0.009** | 2/5 | **0** | −0.038 | 0.88 |
| π = 0.95，均匀先验 | −0.008 | 2/5 | 0 | −0.027 | 0.88 |

**π 的选择**：按事先声明的规则选中 π = 0.95。π = 0.8 落后 0.007，超过 0.005 的平局线。留一元件敏感性分析中，4/5 次仍选 0.95；去掉 IRF6 时选 0.8。

**同预算对照**（在 π = 0.95 的同一组选点上）：

|---|---|---|
| disc 选点 + meta_ridge | −0.020 | +0.011 |
| random 选点 + meta_ridge | −0.050 | +0.041 |
| random 选点 + matched_cal | −0.104 | +0.095 |

**逐元件**（k = 8，rho_bma）：

| 元件 | matched | 最佳单轨道 | v1 | v2（π = 0.95） | 锚点质量 |
|---|---|---|---|---|---|
| PKLR-48h | 0.656 | 0.655 | 0.546 | 0.647 | 0.99 |
| IRF6 | 0.435 | 0.563 | **0.522** | 0.436 | 0.995 |
| HNF4A | 0.338 | 0.358 | 0.248 | 0.300 | 0.84 |

| F9 | 0.454 | 0.510 | 0.459 | 0.489 | 0.76 |

### 结论

1. **保住做到了，救回丢了。**
   - 损害从 3/5 降到 0/5，平均差从 −0.047 缩到 −0.009。
   - 但开发集上唯一的救回例子 IRF6（v1 比 matched 高 0.088）在 v2 中消失：8 个实测值之后锚点仍有 0.995 的后验质量。即使 π = 0.5，IRF6 的锚点质量也有 0.91。可见这里不是先验太强，而是 8 个标签本身就支持匹配平均。v1 在 IRF6 的增益来自对很多轨道做平均，而不是"有证据表明匹配轨道不对"。
2. **用 8 个标签做仿射校正有害**：`matched_cal` 平均比原样使用低 0.10，原因是斜率会被翻成负的。这直接证实了评审担心的翻转风险，也是 v2 把锚点斜率先验放在正值上的理由。
3. **v2 胜过以元数据为中心的岭回归**（+0.011 / +0.041），但仍不如原样使用匹配平均（−0.009）。在开发集上，最强的简单基线就是"什么都不做"。
4. **家族先验没有带来改进**：
   - all 场景与均匀先验几乎相同；
   - hide_matched 场景 k = 8 时为 0.351，v1 为 0.363（k = 16 时 0.386 对 0.383）。
   保留它只是为了满足"复制轨道不改变预测"这一设计要求。在检验集和 Siraj 上，它仍作为消融报告。
5. **停止规则出现评审预言的惯性**：锚点一直是 MAP，所以 disc_stop 在所有元件上都在最少的 3 个标签时停下。停止规则需要重设计，例如改用预期信息量或预测分布的稳定性。在此之前，disc_stop 不作为 v2 的结论。

### 冻结的 v2（用于 Kircher 检验集复核和之后的 Siraj 预注册）

```
python pilot/scripts/proxy_select.py pilot --common-eval --anchor-prior 0.95 --family-prior --controls
```

其余参数为默认值（α = 0.1，β = 0.5，锚点斜率 sd 系数 0.5，池 50%，200 次重复，seed 0）。主输出：k = 8 的 rho_bma。

**开发集对"安全网"主张的含义**：按评审的停止条件，v2 能超过简单的元数据适配，但在开发集上看不到"控制损害的前提下救回"。检验集上，v1 明显超过 matched 的区域有 LDLR（+0.27）、MSMB（+0.12）和 HBG1（+0.07），它们才是真正考验救回的地方。下一步就是在 Kircher 检验集上运行冻结的 v2，作为描述性复核。

## Kircher 检验集复核（冻结后运行，描述性，2026-10-29）

冻结的 v2 在 commit d389586 中提交并推送，之后才运行检验集。按评审意见，Kircher 已是开发历史，所以这一步不算确证。分析单位为 11 个区域；完整表见 `results/a1/v2_test_configs.tsv` 和 `v2_test_long.tsv`。

**部署场景（all，保留匹配轨道）**

| 区域 | matched | v1，k = 8 | v2，k = 8 | v2，k = 16 | 锚点质量 k = 8 → 16 |

**同预算对照**（k = 8，同一组 disc 选点）：
- v2 − disc + meta_ridge = −0.001（k = 16 时为 0.000），两者打平；
- v2 − random + meta_ridge = +0.032；
- random + matched_cal 平均比 matched 低很多，LDLR 甚至降到 0.139。

**hide_matched（v1 + 家族先验）**：disc 0.373 对 v1 0.370，random 0.283 对 0.286。家族先验基本没有影响。

### 判断

1. **保住在检验集上成立**：k = 8 时与 matched 平均持平，k = 16 时 +0.018，没有区域受损。v1 的主要问题（7/11 个区域受损）得到解决。
2. **救回只是部分的，而且需要更多标签**：
   - 8 个标签时，LDLR 只从 0.25 升到 0.29，而 v1 是 0.53；
   - 16 个标签时升到 0.41。
   随着标签增加，锚点质量下降，方法逐渐转向数据支持的轨道。这正是预期的"先信元数据、证据够了再改"的行为，但速度慢。
3. **按评审的停止条件**：在同一组选点上，v2 的推断与以元数据为中心的岭回归打平，没有超过它。两者相对随机选点下的同一对照都高约 0.03。所以 v2 目前的增量主要来自**选点**（disc），而不是锚点后验本身。"贝叶斯锚点后验优于简单元数据适配"这一主张不成立；"安全网"能不能成立，取决于在 Siraj 上能否在受控损害下救回。
4. **对论文主张的含义**：能站住的是三点：
   - (a) 用 8 个标签做仿射校正会翻转匹配平均，有害；
   - (b) 加入元数据锚点后，保住达到非劣效水平；
   - (c) disc 选点同时提升 v2 和简单对照（约 +0.03）。
   救回需要约 16 个标签。
